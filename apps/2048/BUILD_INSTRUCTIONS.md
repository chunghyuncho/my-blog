이미 승인된 설계 계획을 그대로 구현한다.

## 작업 디렉토리
`C:\Users\15Z90S\Desktop\my-blog` (블로그 프로젝트 루트)

## 필독 파일
`C:\Users\15Z90S\Desktop\my-blog\apps\2048\spec.md`

이 파일에 개요, 파일 구조, 핵심 로직 설계, UI/UX, 접근성, 구현 순서 체크리스트(5절)가 모두 정의되어 있다.
**spec.md의 설계와 5절 체크리스트를 그대로 따라 구현하라.** 임의로 설계를 바꾸지 마라 (사소한 구현 디테일은 재량 허용).

## 네가 만들 파일
- `apps/2048/index.html`
- `apps/2048/style.css`
- `apps/2048/script.js`

(spec.md는 이미 존재하므로 건드리지 않는다.)

## 제약 사항 (반드시 지킬 것)
- **`apps/2048/` 폴더 밖의 어떤 파일도 만들거나 수정하지 마라.** 블로그 루트의 `index.html`, `css/`, `js/`, `posts/` 등은 이번 단계에서 절대 건드리지 않는다 (Embed는 별도 단계에서 처리됨).
- 프레임워크/빌드 도구 금지. 순수 HTML, CSS, 바닐라 JS만 사용.
- 외부 라이브러리 사용하지 않는다 (spec.md 기준 로직이 단순해 직접 구현 가능).
- 반응형 + 모바일 터치 스와이프 지원 필수 (spec.md 4.4절).
- 접근성 요구사항 반영 필수 (spec.md 4.5절).
- 점수판(현재 점수 + 최고 점수, localStorage 저장) 반드시 포함.

## 완료 후 할 일
1. 세 파일을 모두 작성한다.
2. 브라우저에서 열어 기본 동작(타일 이동, 병합, 점수 증가, 새 타일 생성)을 스스로 한 번 점검한다. 가능하면 로컬에서 파일을 직접 실행하거나 정적 서버로 열어 확인한다.
3. 발견한 이슈가 있으면 직접 수정한다.
4. 완료 보고 시: 구현한 파일 목록, spec.md 대비 달라진 점(있다면 이유 포함), 스스로 확인한 동작 여부를 간단히 요약한다.

## 하지 말아야 할 것
- Review는 네 역할이 아니다 — 정식 Review는 별도의 Review 서브에이전트가 담당하므로, 여기서는 기본적인 자체 점검만 하고 과도한 시간을 쓰지 않는다.
- git 커밋, index.html(블로그 루트) 수정 등 Embed 단계 작업은 하지 않는다.
