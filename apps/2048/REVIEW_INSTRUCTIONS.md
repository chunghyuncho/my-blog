## 네가 할 일
1. **코드 리뷰**: 세 파일을 읽고 spec.md의 요구사항(핵심 로직, UI/UX, 접근성)이 실제로 구현되었는지 대조 확인한다. 버그, 엣지 케이스 누락, 접근성 미비 등을 찾는다.
2. **브라우저 실기 검증**: 로컬 정적 서버(`npx live-server apps/2048` 등)로 실제 브라우저에서 게임을 열어 다음을 확인한다.
   - 초기 로드 시 타일 2개 배치, 점수판 0으로 표시
   - 방향키 4방향 이동 및 병합이 올바르게 동작하는지
   - 이동이 불가능한 방향키 입력 시 새 타일이 생성되지 않는지 (턴 소모 안 함)
   - 점수 증가 및 최고 점수(localStorage) 저장/유지가 정상인지 (새 게임 후에도 BEST 유지)
   - 콘솔에 JS 에러가 없는지
   - 가능하다면 브라우저 창 크기를 모바일 폭으로 줄여 반응형 레이아웃이 깨지지 않는지 확인 (터치 이벤트 시뮬레이션이 어렵다면 최소한 레이아웃과 코드 로직으로 스와이프 처리를 검증)
   - 키보드만으로 "새 게임" 등 버튼에 포커스/조작이 가능한지 (접근성)
   - 가능하면 게임 오버 또는 승리(2048) 시나리오도 코드 흐름을 강제로 유도하거나 로직을 직접 검토하여 오버레이가 올바르게 뜨는지 확인
3. **문제 발견 시 직접 수정한다.** (`apps/2048/` 폴더 안의 파일만 수정 가능. 폴더 밖은 절대 건드리지 않는다.)
4. **`apps/2048/review.md` 파일을 작성한다.** 다음 내용을 포함할 것:
   - 검증 항목별 결과 (통과/실패/수정함)
   - 발견한 문제와 수정 내역
   - 남은 이슈나 한계(있다면)
   - 최종 결론: Embed(블로그에 카드 추가) 단계로 넘어가도 되는지 여부

## 제약 사항
- `apps/2048/` 폴더 밖의 어떤 파일도 만들거나 수정하지 마라 (블로그 루트 index.html, css/, js/ 등은 건드리지 않는다 — Embed는 별도 단계).
- git 커밋은 하지 않는다 (Embed 단계에서 처리).
- 프레임워크/빌드 도구를 추가하지 않는다.
