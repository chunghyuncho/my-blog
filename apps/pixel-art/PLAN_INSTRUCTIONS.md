# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 역할
너는 이 프로젝트(my-blog 웹앱 포트폴리오)의 **Plan 담당 서브에이전트**다.
코드를 구현하지 말고, 오직 계획만 작성한다.

## 작업 디렉토리
`C:\Users\15Z90S\Desktop\my-blog` (블로그 프로젝트 루트)

## 사용자 요청
- 픽셀 아트 에디터를 만든다.
- 16x16 격자에 도트(칸)를 클릭/드래그로 찍어서 그림을 그린다.
- 색상 팔레트를 제공해 원하는 색을 선택할 수 있어야 한다.
- 완성한 그림을 PNG 파일로 저장(다운로드)할 수 있어야 한다.

## 프로젝트 제약 (CLAUDE.md 기준)
- HTML, CSS, JavaScript만 사용 (프레임워크/빌드도구 금지).
- 앱은 `apps/pixel-art/` 폴더 안에 완전히 독립적으로 구성 (블로그의 다른 파일은 건드리지 않음, 아직 건드리지도 말 것).
- 외부 라이브러리 사용 최소화. CDN은 허용하지만 가급적 직접 구현 (PNG 저장은 `<canvas>`의 `toDataURL`/`toBlob`으로 라이브러리 없이 구현 가능).
- 모바일에서도 사용할 수 있어야 한다 (터치로 그리기 지원).

## 네가 할 일
1. 에디터 설계를 구상한다:
   - 16x16 격자 데이터 구조 및 상태 관리 (각 셀의 색상 값)
   - 격자를 어떻게 그릴지: `<canvas>` 기반 vs `<div>`/`<button>` 그리드 기반 — 장단점 비교 후 하나를 결정 (PNG 저장 용이성 고려 시 canvas 권장, 단 결정은 서브에이전트 재량)
   - 클릭 및 드래그로 연속해서 칠하기 (마우스 down 유지 중 이동 시 계속 칠해짐) 처리 방식
   - 지우개 기능 (선택 사항으로 고려)
   - 색상 팔레트 UI: 기본 제공 색상 목록 + 커스텀 색상 선택(`<input type="color">`) 포함 여부
   - 현재 선택된 색상 표시 방식
   - "전체 지우기" 기능
   - PNG 저장 방식: 16x16 셀을 실제 이미지 픽셀로 어떻게 매핑할지(예: 각 셀 1px로 16x16 PNG를 만들지, 확대된 해상도로 저장할지) 결정하고 근거를 남긴다
   - 모바일 터치 드로잉 지원 방안 (스크롤과 충돌하지 않도록)
   - 반응형 레이아웃 및 시각 디자인 개요
   - 접근성 고려사항 (키보드로 팔레트 선택 가능 여부 등, 격자 자체의 완전한 키보드 대체는 필수 아님 - 시도 가능하면 좋음)
2. 파일 구조를 정한다 (예: `apps/pixel-art/index.html`, `apps/pixel-art/style.css`, `apps/pixel-art/script.js` 등).
3. 위 내용을 정리해서 `apps/pixel-art/spec.md` 파일로 저장한다.
   - spec.md에는: 개요, 파일 구조, 핵심 로직 설계(격자/드로잉/팔레트/PNG 저장), UI/UX, 접근성, 구현 순서 체크리스트를 포함할 것.

## 하지 말아야 할 것
- `apps/pixel-art/` 폴더 밖의 어떤 파일도 만들거나 수정하지 않는다.
- `index.html`, `script.js` 등 실제 구현 코드를 작성하지 않는다 (Plan 단계이므로 spec.md만 작성).
