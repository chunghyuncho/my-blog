## 네가 할 일
1. **코드 리뷰**: 세 파일을 읽고 spec.md의 요구사항(격자/드로잉/팔레트/PNG 저장/접근성)이 실제로 구현되었는지 대조 확인한다. 버그, 엣지 케이스 누락, 접근성 미비 등을 찾는다.
2. **브라우저 실기 검증**: 로컬 정적 서버(`npx live-server apps/pixel-art` 등)로 실제 브라우저에서 열어 다음을 확인한다.
   - 16x16 격자가 정상적으로 렌더링되는지
   - 클릭 및 드래그로 셀에 색이 칠해지는지 (연속 드래그 시 여러 셀이 자연스럽게 칠해지는지)
   - 팔레트에서 색을 바꾸면 이후 칠하는 색이 바뀌는지, 커스텀 색상 선택도 동작하는지
   - 지우개 기능이 정상 동작하는지 (칠한 셀을 지울 수 있는지)
   - "전체 지우기"가 정상 동작하는지
   - "PNG로 저장" 버튼을 눌렀을 때 실제로 유효한 PNG 파일(또는 다운로드 트리거)이 생성되는지 — 가능하면 저장된 이미지의 픽셀 데이터나 Blob을 직접 확인해 색이 올바르게 반영됐는지 검증
   - 콘솔에 JS 에러가 없는지
   - 모바일 폭(예: 375px)에서 레이아웃이 깨지지 않는지, 터치 드로잉 로직이 코드상 올바른지
   - 키보드로 팔레트/버튼 조작이 가능한지 (접근성)
3. **문제 발견 시 직접 수정한다.** (`apps/pixel-art/` 폴더 안의 파일만 수정 가능. 폴더 밖은 절대 건드리지 않는다.)
4. **`apps/pixel-art/review.md` 파일을 작성한다.** 다음 내용을 포함할 것:
   - 검증 항목별 결과 (통과/실패/수정함)
   - 발견한 문제와 수정 내역
   - 남은 이슈나 한계(있다면)
   - 최종 결론: Embed(블로그에 카드 추가) 단계로 넘어가도 되는지 여부

## 제약 사항
- `apps/pixel-art/` 폴더 밖의 어떤 파일도 만들거나 수정하지 마라 (블로그 루트 index.html, css/, js/, 다른 앱 등은 건드리지 않는다 — Embed는 별도 단계).
- git 커밋은 하지 않는다 (Embed 단계에서 처리).
- 프레임워크/빌드 도구를 추가하지 않는다.
