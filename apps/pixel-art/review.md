## 발견한 문제와 수정 내역

### 문제 1 (수정함): 빠른 드래그 시 칠해지지 않는 셀(공백) 발생
- **증상**: 마우스를 빠르게 드래그하면 브라우저의 `mousemove` 이벤트가 모든 픽셀 이동을 포착하지 못해, 이전에 칠한 셀과 새로 칠한 셀 사이에 이동 경로상의 셀들이 칠해지지 않고 건너뛰는 현상을 실제 브라우저에서 재현 확인함(스크린샷으로 3개 셀만 칠해지고 사이 공백 발생을 확인).
- **원인**: `script.js`의 `mousemove`/`touchmove` 핸들러가 `paintCell(index)`만 호출하여 현재 셀 하나만 칠하고, 직전 셀과 현재 셀 사이의 경로를 보간하지 않았음.
- **수정**: `paintCell` 기반의 `paintLine(fromIndex, toIndex)` 함수를 Bresenham 직선 알고리즘으로 추가하고, `mousemove`/`touchmove` 핸들러에서 `paintCell(index)` 대신 `paintLine(state.lastPaintedIndex, index)`를 호출하도록 변경. 수정 후 동일한 드래그 재현 시 경로상의 모든 셀이 끊김 없이 칠해짐을 스크린샷으로 재확인함.
- **수정 파일**: `apps/pixel-art/script.js` (`paintLine` 함수 추가, `mousemove`/`touchmove` 리스너 수정)

## 남은 이슈/한계

- "전체 지우기"의 `confirm()` 네이티브 다이얼로그는 헤드리스 브라우저 자동화 환경에서 자동으로 "취소"로 처리되는 특성이 있어, 실제 사용자 클릭 흐름으로는 다이얼로그 자체의 렌더링을 스크린샷으로 담을 수 없었다(로직은 `window.confirm`을 임시로 강제 `true` 처리해 별도로 검증 완료). 실제 사용자 브라우저에서는 표준 `confirm()` 동작이므로 문제 없음.
- 격자 자체의 완전한 키보드 대체 내비게이션은 spec.md에서 "선택 사항"으로 명시되어 있으나 이미 구현되어 있고 정상 동작을 확인함(추가 조치 불필요).
- `willReadFrequently` 관련 콘솔 경고(성능 힌트, 에러 아님)가 표시되었으나 이는 리뷰 스크립트가 디버깅 목적으로 `getImageData`를 반복 호출했기 때문이며, 앱 자체의 정상 동작(렌더링/저장)에서 발생한 것이 아니다. 앱 코드 수정 불필요.
- 이번 리뷰는 Chromium 기반 브라우저 1종에서만 수행했다(다른 브라우저 엔진 교차 테스트는 범위 밖).
