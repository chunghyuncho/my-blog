# 픽셀 아트 에디터 — 설계 계획 (spec.md)

## 1. 개요

16x16 격자에 클릭/드래그로 도트를 찍어 그림을 그리고, 색상 팔레트에서 색을 선택하며, 완성한 그림을 PNG로 저장(다운로드)할 수 있는 순수 HTML/CSS/JavaScript 웹앱. 프레임워크·빌드도구 없이 `apps/pixel-art/` 폴더 안에서 완전히 독립적으로 동작하며, 데스크톱과 모바일(터치) 모두 지원한다.

- 대상 경로: `apps/pixel-art/`
- 기술 스택: 순수 HTML, CSS, JavaScript (외부 라이브러리 없음, CDN 미사용 — PNG 저장까지 `<canvas>` 네이티브 API만으로 구현 가능하므로 별도 라이브러리 불필요)
- 데이터 지속성: 없음 (새로고침 시 초기화). 로컬 저장(localStorage)은 이번 범위 밖으로 하고, 필요 시 추후 확장 항목으로만 남긴다.

## 2. 파일 구조

```
apps/pixel-art/
├── spec.md      # 본 설계 문서 (Plan 단계 산출물)
├── index.html   # 마크업 구조 (헤더, 캔버스 영역, 팔레트, 툴바, 버튼)
├── style.css    # 레이아웃, 반응형, 팔레트/버튼 스타일, 다크/라이트 배려
└── script.js    # 상태 관리, 렌더링, 입력 처리(마우스/터치), PNG 저장 로직
```

Build 단계에서 위 3개 파일(index.html, style.css, script.js)을 생성한다. 이미지 리소스나 별도 폰트 파일은 사용하지 않는다(시스템 폰트 사용).

## 3. 핵심 데이터 구조 및 상태 관리

- 격자는 16x16 = 256개 셀을 가진 1차원 배열 `pixels`로 관리한다: `pixels[y * 16 + x] = colorString | null`
  - `null`(또는 `"transparent"`/빈 문자열)은 "칠해지지 않음" 상태를 의미하며, PNG 저장 시 완전 투명 알파(alpha=0)로 매핑한다.
  - 색상 값은 `"#rrggbb"` 형식의 문자열로 통일 저장한다.
- 전역 상태 객체 예:
  ```js
  const state = {
    grid: new Array(256).fill(null), // 셀 색상
    currentColor: '#000000',
    tool: 'draw',       // 'draw' | 'erase'
    isPointerDown: false,
    lastPaintedIndex: -1, // 같은 셀 중복 처리 방지용
  };
  ```
- 렌더링은 "상태 → 화면" 단방향으로: 셀 클릭/드래그 시 `grid` 배열을 갱신하고, 해당 셀만 다시 그리거나(성능상 유리) 캔버스 전체를 다시 그린다(16x16 규모에서는 전체 재렌더링도 충분히 가볍다).

## 4. 격자 렌더링 방식: `<canvas>` vs `<div>` 그리드 비교 및 결정

| 항목 | `<canvas>` | `<div>`/`<button>` 256개 |
|---|---|---|
| PNG 저장 | `toDataURL()`/`toBlob()`으로 매우 간단 | DOM을 별도 canvas로 다시 그려야 해서 이중 작업 필요 |
| 렌더링 성능 | 256셀 정도는 문제 없음, 좌표 계산만 하면 됨 | DOM 256개는 무겁진 않지만 리플로우/이벤트 리스너 다수 발생 |
| 입력 처리 | 마우스/터치 좌표 → 셀 인덱스 변환 필요(간단한 나눗셈) | 각 요소가 자체 이벤트를 가져 구현이 직관적 |
| 접근성(키보드 포커스 등) | 개별 셀에 포커스를 줄 수 없어 완전한 키보드 내비게이션이 어려움 | 각 셀이 개별 포커스 가능한 요소가 될 수 있어 유리 |
| 확대/축소, 격자선 표시 | 직접 그려야 함(간단한 `strokeRect` 반복) | CSS border로 간단히 표현 가능 |

**결정: `<canvas>` 기반으로 구현한다.**

근거:
1. PNG 저장이 핵심 요구사항이며, canvas 기반이면 `toDataURL('image/png')` 한 줄로 해결되어 구현 복잡도와 버그 가능성이 가장 낮다.
2. 지침에서도 "PNG 저장 용이성 고려 시 canvas 권장"으로 명시했고, 라이브러리 없이 직접 구현이라는 제약과도 가장 잘 맞는다.
3. 16x16 규모에서는 canvas 재렌더링 비용이 무시할 수준이라 성능상 손해가 없다.
4. 접근성 손실(격자 자체의 완전한 키보드 대체)은 지침에서 "필수 아님"으로 명시되어 있으므로, 격자 바깥의 팔레트/버튼 조작에 집중해 키보드 접근성을 확보하는 것으로 절충한다(8절 참고).

렌더링 세부:
- 캔버스의 논리적 해상도(내부 픽셀 수)는 셀 크기 × 16으로 설정하고, CSS로 화면에 표시되는 크기를 반응형으로 확대한다(예: 캔버스 attribute `width/height`는 실제 저장 해상도와 별개로, 표시용 확대 배율을 CSS에서 처리).
- 셀 사이 격자선은 1px 실선(연한 회색)으로 그려 셀 구분을 돕는다. 격자선 표시 여부는 토글하지 않고 항상 표시(단순화).
- 매 렌더링 시 전체 캔버스를 지우고 256개 셀을 순회하며 `fillRect`로 그린 뒤 격자선을 그린다.

## 5. 드로잉 처리 (클릭 및 드래그)

공통 로직: 화면 좌표 → 캔버스 내부 좌표 → 셀 (col, row) 인덱스로 변환하는 헬퍼 함수 `getCellFromEvent(event)`를 만든다. 이 함수는 `canvas.getBoundingClientRect()`와 캔버스의 실제 논리적 크기 비율을 이용해 마우스/터치 좌표를 셀 인덱스로 매핑한다.

### 마우스(데스크톱)
- `mousedown`: `state.isPointerDown = true`, 클릭된 셀을 즉시 칠하고 `lastPaintedIndex` 갱신.
- `mousemove`: `isPointerDown`이 true일 때만 좌표를 셀로 변환, 이전에 칠한 셀과 다르면 칠하기(같은 셀 반복 호출로 인한 불필요한 재렌더링 방지).
- `mouseup`(캔버스 안/밖 모두 대응, `window`에 리스너 등록 권장): `isPointerDown = false`.
- `mouseleave`로 캔버스 밖으로 나가도 `mousedown` 상태가 유지되도록 `mouseup`은 `window` 레벨에서 감지한다(밖에서 버튼을 뗐을 때도 정확히 종료되도록).

### 터치(모바일)
- `touchstart`: `preventDefault()`로 스크롤/확대 제스처와 충돌 방지, 첫 터치 지점 셀을 칠하고 `isPointerDown = true`.
- `touchmove`: `preventDefault()` 호출 후 `event.touches[0]` 좌표로 셀 계산 및 칠하기(모바일에서 손가락으로 드래그 시 화면 스크롤이 되지 않도록 캔버스 자체에 `touch-action: none` CSS도 함께 적용해 이중으로 방지).
- `touchend`/`touchcancel`: `isPointerDown = false`.
- 캔버스에는 CSS `touch-action: none;`을 지정해 브라우저 기본 스크롤/핀치줌 제스처가 캔버스 위에서 발동하지 않게 한다. 캔버스 바깥(페이지 전체)의 스크롤은 그대로 유지된다.

### 공통 헬퍼: `paintCell(index)`
- 현재 `state.tool`이 `'draw'`면 `grid[index] = state.currentColor`, `'erase'`면 `grid[index] = null`.
- 값이 실제로 바뀐 경우에만 다시 렌더링(불필요한 반복 렌더 방지).

## 6. 지우개 기능

- 팔레트 영역 근처에 "지우개" 토글 버튼을 둔다(선택 시 `state.tool = 'erase'`, 해제/다른 색 선택 시 `'draw'`로 복귀).
- 지우개 선택 중에는 버튼에 활성 스타일(예: 테두리 강조)을 주어 현재 도구를 시각적으로 표시한다.
- 다른 색상을 팔레트에서 클릭하면 자동으로 `tool = 'draw'`로 전환되어, 지우개 상태에서 색을 눌러도 바로 그리기로 복귀하게 한다(직관적 UX).
- 구현 난이도가 낮고 사용성을 높이므로 "선택 사항"이지만 포함하기로 결정한다.

## 7. 색상 팔레트 UI

- 기본 제공 색상: 16색 내외의 스와치 버튼(예: 검정, 흰색, 회색, 빨강, 주황, 노랑, 연두, 초록, 청록, 하늘색, 파랑, 남색, 보라, 분홍, 갈색, + 지우개용 체크무늬 아이콘 등). 각 스와치는 `button` 요소로 만들어 클릭 시 `state.currentColor`를 갱신하고 `tool = 'draw'`로 전환.
- 커스텀 색상: `<input type="color">` 하나를 팔레트 끝에 배치해, 사용자가 원하는 임의의 색을 고를 수 있게 한다. `input` 이벤트로 값이 바뀔 때마다 `state.currentColor`를 갱신하고 해당 색을 "현재 선택된 색"으로 표시(스와치 목록에는 없어도 무방, 별도의 "커스텀 색" 슬롯으로 취급).
- 현재 선택된 색상 표시: 팔레트 상단(또는 툴바)에 작은 사각형 미리보기(`#current-color-preview`)를 두고 `background-color`를 `state.currentColor`로 항상 동기화. 선택된 스와치 버튼 자체에는 `aria-pressed="true"`와 시각적 테두리(outline)를 부여해 어떤 색이 선택됐는지 이중으로 표시한다.

## 8. 접근성 고려사항

- 팔레트의 색상 스와치와 지우개 버튼은 모두 `<button>` 요소로 만들어 기본적으로 Tab 키 포커스 이동과 Enter/Space 활성화를 지원한다(HTML 시맨틱만으로 확보).
- 각 스와치 버튼에 `aria-label="검정색 선택"`처럼 색 이름을 명시한 레이블을 부여하고, 현재 선택 상태는 `aria-pressed`로 노출한다.
- 커스텀 색상 `<input type="color">`에는 `aria-label="사용자 지정 색상 선택"`을 부여.
- "전체 지우기", "PNG로 저장" 버튼도 명확한 텍스트 레이블(아이콘만 사용하지 않음)을 사용해 스크린리더 사용자도 기능을 알 수 있게 한다.
- 격자(캔버스) 자체의 완전한 키보드 대체(화살표 키로 셀 이동 + 스페이스로 칠하기 등)는 필수 구현 대상은 아니지만, 여유가 되면 다음 방식으로 시도한다: 캔버스에 `tabindex="0"`을 주고 포커스 시 방향키로 커서 셀을 이동, Enter/Space로 현재 색을 칠하는 로직을 추가할지 Build 단계 재량으로 남긴다(스펙상 "가능하면 추가"하는 선택 항목으로 명시).
- 색 대비: 배경/전경색은 무난한 명도 대비를 확보하고, 다크 모드 강제 없이 시스템 기본을 따르되 필요 시 `prefers-color-scheme`로 최소한의 다크 배경 대응을 고려한다(우선순위 낮음, 시간 남으면).

## 9. "전체 지우기" 기능

- "전체 지우기" 버튼 클릭 시 `state.grid`를 전부 `null`로 초기화하고 캔버스를 다시 그린다.
- 실수 클릭 방지를 위해 `confirm()` 네이티브 다이얼로그로 1차 확인을 거친다(별도 라이브러리 없이 간단히 구현 가능한 최소한의 안전장치).

## 10. PNG 저장 방식

**결정: 16x16 셀을 확대된 해상도(예: 셀당 32px, 총 512x512px)로 저장한다. 단, 저장용으로 별도의 "오프스크린 캔버스"를 만들어 픽셀 아트 특유의 선명한 계단식 확대(안티앨리어싱 없는 nearest-neighbor 확대)로 렌더링한다.**

근거:
- 16x16 그대로(각 셀 1px) 저장하면 파일은 정확하지만, 대부분의 이미지 뷰어/블로그 카드 미리보기에서 너무 작게 표시되어 실용성이 떨어진다.
- 화면에 보이는 캔버스(확대되어 렌더링된 편집 캔버스)를 그대로 `toDataURL()`로 저장하면 반응형 크기에 따라 저장 해상도가 들쭉날쭉해지는 문제가 있다. 따라서 화면 표시용 캔버스와, 저장 전용으로 고정 배율(예: ×32)로 다시 그리는 오프스크린 캔버스를 분리한다.
- 확대 시 `ctx.imageSmoothingEnabled = false`를 설정해(만약 이미지 스케일링 API를 쓸 경우) 픽셀이 흐릿해지지 않고 또렷한 픽셀 아트 느낌을 유지한다. 실제로는 각 셀을 `fillRect(col*scale, row*scale, scale, scale)`로 직접 그리므로 스무딩 옵션과 무관하게 항상 또렷하다.
- 칠해지지 않은 셀(`null`)은 `fillRect`를 호출하지 않고 그대로 두어(초기 캔버스를 `clearRect`로 완전 투명하게 만든 뒤 시작) 알파 채널이 0인 투명 배경 PNG로 저장되게 한다. 이렇게 하면 사용자가 배경을 칠하지 않은 부분은 투명하게 유지되어 다양한 용도(스티커 등)로 활용 가능하다.
- 저장 절차: `offscreenCanvas(512x512)` 생성 → `grid` 배열 순회하며 각 셀 색을 32x32 사각형으로 그림 → `canvas.toBlob(blob => { ... }, 'image/png')`로 Blob 생성 → `URL.createObjectURL(blob)`을 임시 `<a download="pixel-art.png">` 요소의 href로 설정 후 `click()`으로 다운로드 트리거 → 사용 후 `URL.revokeObjectURL()`로 정리.
- 파일명은 고정값 `pixel-art.png` 사용(타임스탬프 등 추가는 선택 사항, 여유 있으면 `pixel-art-YYYYMMDD-HHmmss.png` 형태로 유니크하게).

## 11. 모바일 터치 드로잉 지원 방안 (스크롤 충돌 방지)

- 캔버스 요소에 CSS `touch-action: none;`을 지정해 브라우저가 캔버스 위 터치 제스처를 스크롤/줌으로 해석하지 않게 한다.
- `touchstart`/`touchmove` 이벤트 핸들러에서 `event.preventDefault()`를 호출해 이중으로 기본 동작(스크롤, 핀치 줌, 길게 눌러 컨텍스트 메뉴 등)을 막는다.
- 페이지 전체는 일반적인 세로 스크롤이 가능해야 하므로, `touch-action: none`은 캔버스 요소에만 적용하고 `body`/`html`에는 적용하지 않는다.
- 팔레트 버튼 등 캔버스 밖 UI 요소는 기본 터치 동작(탭)을 그대로 사용해 별도 처리가 필요 없다.
- 캔버스의 화면 표시 크기는 뷰포트 너비에 따라 CSS로 유동적으로 조절하되(`max-width: 100%`, 정사각형 유지), 내부 좌표 변환 시 `getBoundingClientRect()`로 실제 표시 크기를 읽어 셀 인덱스를 정확히 계산한다.

## 12. 반응형 레이아웃 및 시각 디자인 개요

- 레이아웃 구조(위→아래, 좁은 화면 기준 세로 스택; 넓은 화면에서는 캔버스와 팔레트를 좌우로 배치할 수도 있으나 단순화를 위해 항상 세로 스택으로 통일):
  1. 헤더: 앱 제목("픽셀 아트 에디터") 및 한 줄 설명
  2. 캔버스 영역: 16x16 격자 (정사각형, 반응형 크기, 최대 폭 제한)
  3. 툴바: 현재 색상 미리보기, 지우개 토글 버튼
  4. 팔레트: 기본 색상 스와치 그리드 + 커스텀 색상 피커
  5. 액션 버튼: "전체 지우기", "PNG로 저장"
- 색상/스타일: 블로그 전반의 톤과 크게 어긋나지 않는 무난한 배색(밝은 배경, 진한 텍스트, 버튼은 은은한 테두리와 hover 시 배경 변화). 별도 다크 모드 강제 구현은 하지 않되 시스템 설정을 따르는 최소한의 `prefers-color-scheme` 대응은 선택적으로 고려.
- 뷰포트 최소 폭(약 360~400px)에서도 좌우 스크롤 없이 모든 요소가 보이도록 팔레트 스와치는 `flex-wrap`으로 줄바꿈, 캔버스는 `width: min(90vw, 480px)` 형태로 크기를 제한한다.
- 버튼과 스와치의 터치 타깃 크기는 최소 40x40px 내외로 확보해 모바일에서 오터치를 줄인다.
