클로드 코드와 함께 이 블로그를 처음부터 만들면서, 프레임워크 없이도 세 가지 언어가 각자 어떤 역할을 맡는지 다시 한번 명확히 정리할 수 있었습니다.

## HTML — 구조

`index.html`과 `post.html`은 정말 뼈대 역할만 합니다. 헤더, 다크모드 토글 버튼, 글 목록/본문이 들어갈 빈 컨테이너(`#post-list`, `#post-container`)만 정의해두고, 실제 내용은 전부 JavaScript가 채워 넣습니다. 마크다운을 변환한 HTML도 결국 이 구조 위에 얹히는 것뿐이라는 점이 흥미로웠습니다.

## CSS — 표현

색상, 여백, 타이포그래피를 커스텀 프로퍼티(`--color-bg`, `--color-text` 등)로 선언해두고, `data-theme` 속성값에 따라 값만 바꿔치기하는 방식으로 다크모드를 구현했습니다. 로직은 JavaScript에 있지만, "라이트면 이 색, 다크면 저 색"이라는 실제 표현은 전부 CSS 쪽 책임이라는 역할 분리가 명확했습니다. `clamp()`로 화면 폭에 따라 글자 크기가 자연스럽게 늘어나게 한 것도 미디어 쿼리를 줄여준 부분이었습니다.

## JavaScript — 동작과 데이터

세 언어 중 가장 많은 일을 합니다.

- `fetch()`로 `posts.json`과 각 마크다운 파일을 읽어옵니다.
- 직접 만든 프론트매터 파서로 `title`, `date`, `tags` 같은 메타데이터를 추출합니다.
- `marked.js`로 마크다운 본문을 HTML로 변환합니다.
- `localStorage`와 `prefers-color-scheme`을 조합해 다크모드 상태를 결정하고 저장합니다.
- 결과를 HTML의 빈 컨테이너에 채워 넣습니다.

결국 HTML은 "어디에 무엇이 들어갈지"를, CSS는 "어떻게 보일지"를, JavaScript는 "무엇을 언제 채울지"를 담당한다는 아주 기본적인 원칙을, 프레임워크 없이 직접 손으로 구현해보면서 다시 체감했습니다.
