## 왜 프레임워크를 쓰지 않았나

작은 개인 블로그에는 거대한 빌드 파이프라인이 필요하지 않다고 생각했습니다. 이 사이트는 다음과 같은 방식으로 동작합니다.

1. 브라우저가 `posts/posts.json`을 읽어 어떤 글이 있는지 확인합니다.
2. 각 마크다운 파일을 `fetch`로 가져옵니다.
3. 프론트매터를 직접 만든 파서로 추출합니다.
4. 본문은 [marked.js](https://marked.js.org/)로 HTML로 변환합니다.

## 코드 예시

프론트매터를 파싱하는 함수는 대략 이런 모양입니다.

```js
export function parseFrontmatter(rawText) {
  // "---"로 둘러싸인 블록을 찾아 key: value 쌍을 추출합니다.
  // 리스트(tags 등)도 간단한 규칙으로 지원합니다.
}
```

> 완벽한 YAML 파서는 필요 없습니다. 이 블로그에 필요한 만큼만 지원하면 충분합니다.

빌드 도구가 없다는 것은 곧, 이 글을 쓰는 지금도 마크다운 파일 하나만 저장하면 새로고침으로 바로 결과를 확인할 수 있다는 뜻입니다.
